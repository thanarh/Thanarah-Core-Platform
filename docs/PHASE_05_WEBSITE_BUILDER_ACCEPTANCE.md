# المرحلة الخامسة — موقع العميل وWebsite Builder

## الحالة

هذه متطلبات التنفيذ والقبول، وليست تقرير إنجاز. البناء مشمول بمهمة
«بناء موقع العيادة للعميل» القائمة؛ لا ينشئ هذا المستند مهمة مكررة،
ولا يعني بدء التنفيذ أو نشر موقع. يبقى اشتراط قبول المراحل السابقة
الموجود في خطة العمل قائمًا، ويحتاج الحجز إلى مسار Smart Clinic العام.

## المحاور ومعايير القبول

1. **مكتبة القوالب:** قوالب عيادات متعددة قابلة للاختيار والمعاينة،
   متجاوبة وتدعم العربية وRTL. لا يغير اختيار قالب أو تجربته موقعًا
   منشورًا قبل الحفظ والنشر الصريحين، ولا تتضمن القوالب شهادات مرضى
   أو تراخيص أو خدمات أو أسعارًا مختلقة.
2. **محرر السحب والإفلات:** إنشاء صفحات وإضافة أقسام مدعومة وترتيبها
   وحذفها وتحرير محتواها، بسحب وإفلات فعليين وبديل قابل للاستخدام
   بلوحة المفاتيح وعلى الهاتف، مع تراجع وإعادة وحفظ مسودة ومعالجة
   تعارض الإصدارات وعدم ضياع التعديلات عند فشل الحفظ. لا ينفذ HTML
   أو JavaScript اعتباطيًا من محتوى عميل.
3. **الأطباء والخدمات:** صفحات وقوائم وتفاصيل مرتبطة ببيانات العيادة
   المعتمدة في Smart Clinic. لا يكشف الموقع معلومات داخلية أو بيانات
   اتصال شخصية غير مصرح بنشرها، ولا ينسخ كتالوجًا مستقلًا يتقادم بصمت.
   يختبر اختفاء الطبيب أو الخدمة عند إيقاف النشر أو التعطيل.
4. **الهوية والنطاق:** تخصيص الاسم والشعار والألوان والخطوط وبيانات
   التواصل والتنقل، وإعداد نطاق تجريبي مع إثبات ملكية النطاق عند الربط.
   يجب منع نسب نطاق إلى عيادتين أو الاستيلاء على نطاق أو موقع عميل آخر،
   وعدم الثقة بترويسة Host غير معتمدة لتحديد المستأجر. لا تُشترى نطاقات
   أو تُغير سجلات DNS أو إعدادات موقع حي دون موافقة.
5. **الحجز المرتبط بـSmart Clinic:** اختيار الفرع والخدمة والطبيب والوقت
   المتاح من سياسة المنشأة والتوفر الفعلي، ثم ظهور الحجز أو طلبه داخل
   Smart Clinic بحسب السياسة المعتمدة. يمنع التكرار والتزاحم، ولا تُعرض
   حالة تأكيد أو إرسال أو تحقق غير حقيقية. لا تُخزن بيانات المرضى أو
   مواعيدهم في وثيقة الموقع العامة أو لقطات إصداراته.
6. **المعاينة والنشر واسترجاع الإصدارات:** مسودة ومعاينة خاصة منفصلتان
   عن النسخة العامة، ومعاينات للهاتف والحاسوب، وإصدارات منشورة محفوظة
   يمكن معرفة صاحبها ووقت نشرها ومعاينتها واسترجاعها بإجراء صريح مدقق.
   النشر والاسترجاع متزامنان وآمنان من التكرار والتعارض، ولا يغير فشل
   أي منهما النسخة العامة أو يسقط المسودة. يُثبت ظهور النسخة المختارة
   من طلب جديد، لا من لقطة أو ذاكرة متصفح قديمة.

## شرط الإغلاق الذي حدده المستخدم

**إنشاء موقع عيادة كامل ونشره على نطاق تجريبي.**

ويُثبت بالسيناريو التالي على عيادة وبيانات اصطناعية:

- اختيار قالب وتحريره بالسحب والإفلات وتخصيص الهوية.
- إنشاء الرئيسية وصفحات الأطباء والخدمات والتواصل والحجز، دون اختلاق
  نصوص امتثال أو سياسات قانونية أو بيانات منشأة حقيقية.
- فحص المعاينة على الحاسوب والهاتف، وبقاء الموقع المنشور دون تغيير
  أثناء تعديل المسودة.
- نشر نسخة أولى على نطاق تجريبي معتمد، وفتحها من جلسة زائر مستقلة
  دون جلسة المحرر، وفحص النطاق وHTTPS والصفحات والأصول.
- إجراء حجز اصطناعي من الموقع وإثبات ظهوره داخل Smart Clinic
  في العيادة والفرع والخدمة الصحيحة، مع بقاء حالات المراجعة واضحة.
- نشر تعديل ثان ثم استرجاع النسخة الأولى والتحقق من المحتوى العام
  فعليًا، مع الحفاظ على الحجز وسجلاته؛ استرجاع الموقع لا يسترجع
  قاعدة المرضى أو يمحو العمليات السريرية.
- اختبار محرر مخوّل ومستخدم غير مخوّل وعيادتين مستقلتين، ومنع تسرب
  المعاينات والمسودات والأصول الخاصة بينهما.

## حدود النشر والجاهزية

- رابط المعاينة داخل بيئة التطوير ليس وحده دليل النشر المطلوب.
  لا يُسجل نجاح النشر قبل وجود عنوان فعلي قابل للوصول والتحقق.
- تُحدد استضافة الاختبار والنطاق والخصوصية والتكاليف قبل النشر.
  نشر المشروع المستضيف خطوة ينفذها المستخدم عند الجاهزية؛ نشر إصدار
  محتوى من المحرر ليس بديلًا عن وجود استضافة منشورة تعمل.
- لا يُفترض دعم نطاقات wildcard أو إضافة أي نطاق تلقائيًا؛ تُراجع
  قيود الاستضافة الفعلية، ويُثبت ربط كل اسم مضيف تجريبي مستخدم.
- لا يعني النشر التجريبي الإذن بنشر إنتاجي، أو بيانات مرضى حقيقية،
  أو تفعيل المدفوعات أو تكامل خارجي غير مهيأ.
