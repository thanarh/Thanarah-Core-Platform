# المرحلة السادسة — المشاريع وGitHub

## الحالة

هذا نطاق تنفيذ ومعايير قبول، وليس تقرير إنجاز. مهمة «إدارة مشاريع
العملاء وGitHub» القائمة تغطي هذه المرحلة وتعتمد على موقع العميل؛
لا ينشئ هذا المستند مهمة مكررة ولا يغير حالة المراحل السابقة.
لم يُنشأ مشروع أو مستودع أو ربط خارجي ولم يحدث نشر بهذا التوثيق.

## المحاور ومعايير القبول

1. **مشروع مستقل لكل عميل عند الحاجة:** سجل مشروع مرتبط بحساب العميل
   والمنشأة، بمالك وفريق ونوع استضافة وبيئات وروابط واضحة. يحدد قرار
   موثق متى تكفي مساحة موقع معزولة ومتى يلزم مشروع برمجي مستقل،
   ولا تنشأ مشاريع أو مستودعات لكل عميل تلقائيًا دون حاجة وموافقة.
2. **مستودعات خاصة وقوالب:** استخدام GitHub بإذن معتمد ومستودعات خاصة
   وقوالب محددة الإصدار، بعد اعتماد المالك أو المنظمة وصلاحيات الفريق.
   لا تنسخ بيانات المرضى أو أسرار العميل أو قيم بيئة التشغيل إلى
   المستودع أو القالب؛ عدم الربط أو نقص الإذن يظهر كتعطل صريح لا كنجاح.
3. **إدارة الإصدارات ومراجعة التغييرات:** طلب تغيير مرتبط بالمشروع،
   يتتبعه فرع وطلب مراجعة وفروقات واختبارات ومراجع وقرار قبول أو رفض.
   تعتمد نتائج الاختبار والموافقة على معرّف التغيير ونسخة البناء نفسها؛
   أي تعديل لاحق يلغي صلاحية الموافقة القديمة للنشر حتى يُراجع.
4. **سجل Deployments وLogs:** سجل لكل محاولة ببيئتها ونسخة المصدر
   والبناء والطالب والموافق والأوقات وحالة التنفيذ ورابط النتيجة
   والسجلات المنقحة. لا تعني جدولة مهمة أو رجوع طلب API بنجاح اكتمال
   النشر؛ يتحقق النظام من نتيجة الموفر ومن النسخة التي تُخدم فعليًا.
5. **موافقات النشر وRollback:** بوابة موافقة خادمية قبل التنفيذ تعرض
   الفروقات والبيئة والاختبارات وأثر التغيير، مع فصل صلاحيات الطلب
   والمراجعة والنشر وفق سياسة المشروع. الاسترجاع عملية معتمدة ومدققة
   إلى إصدار معروف، لا إعادة ضبط عشوائية للمستودع أو قاعدة البيانات.
6. **لوحتا العميل وCTO:** يرى العميل مشاريعه وطلباته ونسخه وحالة
   التغييرات والنشر والموافقات المسموح له بها فقط. تعرض لوحة CTO
   الحالية ملخص المشاريع والاختبارات والطلبات المنتظرة والمحاولات
   الفاشلة والنشر والاسترجاع بحسب الصلاحية، لا لوحة إدارة بديلة منفصلة
   عن نظام الشركة. لا تعني صلاحية مشاهدة لوحة CTO صلاحية نشر تلقائية.

## شرط الإغلاق الذي حدده المستخدم

**تعديل تجريبي ينتقل من الطلب إلى الاختبار ثم النشر والتوثيق.**

يُثبت بالسيناريو التالي على مشروع عميل اصطناعي وبيئة تجريبية معتمدين:

- تحديد ملكية المشروع والمستودع والقالب والبيئة والموافقين، ثم ربط
  مستودع اختبار خاص بعد الإذن، دون لمس مستودع عميل حقيقي.
- إنشاء طلب تعديل بسيط من لوحة العميل، مثل تعديل نص اصطناعي ظاهر،
  وربطه بفرع ومراجعة وفروقات يمكن تتبعها إلى الطلب الأصلي.
- تشغيل اختبارات حقيقية على نسخة التعديل، وتسجيل نتائجها ورابطها
  ونسخة البناء؛ لا تُزرع علامة نجاح أو سجل نشر مصطنع لإغلاق الشرط.
- مراجعة التغيير واعتماد النسخة المختبرة للنشر في البيئة التجريبية
  فقط، ثم اتباع إجراء نشر موفر الاستضافة المعتمد. عندما يتطلب النشر
  إجراء المستخدم، لا ينفذه الوكيل بدلًا عنه ولا يسجل اكتماله قبل التحقق.
- التحقق من ظهور التعديل على عنوان البيئة الفعلي ومن فحص صحتها،
  وتوثيق الطلب والمراجعة والاختبارات والموافقة والإصدار والنتيجة
  في سجل واحد مترابط يظهر في لوحتي العميل وCTO.
- تجربة اختبار فاشل وتغيير بلا موافقة ومحاولة من مستخدم غير مخوّل،
  وإثبات منع النشر في الحالات الثلاث وعدم تكرار التنفيذ عند إعادة الطلب.
- إجراء استرجاع تجريبي بإذن إلى إصدار سابق معلوم، والتحقق من النسخة
  المعروضة واستمرار بيانات العميل والحجوزات، وتوثيق النتيجة.
- اختبار عميلين مستقلين ومنع قراءة مستودع أو سجلات أو إجراءات عميل
  آخر، بما في ذلك فتح الروابط المباشرة ومحاولة تبديل معرّفات المشروع.

## قيود الأمان والتشغيل

- يبدأ التكامل عبر المسار الرسمي وصلاحيات محدودة للمستودعات المطلوبة.
  لا تُطلب رموز وصول في الدردشة ولا توضع في الواجهات أو السجلات.
  اتصال GitHub وحده لا يثبت ملكية كل المستودعات أو إذن النشر عليها.
- لا يملك العميل تغيير عنوان مستودع أو بيئة أو معرّف عملية نشر لتجاوز
  صلاحيات مشروعه. تُفحص إشعارات الموفر ومصدرها وإعادة إرسالها قبل
  أن تغيّر حالة إصدار أو تنسب نجاح اختبار أو نشر إليه.
- لا تنفذ شيفرة مراجعة غير موثوقة داخل خادم المنصة أو ببيانات اعتماد
  نشر أو أسرار إنتاج. تُحدد حدود بيئة الاختبار وسياسة الفروع والمراجعات
  المعتمدة قبل تشغيل الأتمتة.
- تُنقح السجلات على الخادم وتحدد صلاحياتها ومدة حفظها، ولا تكشف
  أسرارًا أو بيانات مرضى. التسجيل المحلي أو رابط سجل غير قابل للوصول
  للمخوّل لا يكفيان لإثبات عمل شاشة السجلات.
- استرجاع الشيفرة أو إصدار الموقع لا يعني استرجاع بيانات المرضى
  أو الحجوزات. تُفحص توافقية مخطط البيانات والترحيلات؛ إذا كان الرجوع
  غير آمن يُمنع مع سبب وخطة بديلة، لا يُنفذ حذف أو ترحيل عكسي ضمني.
- لا نشر إنتاجي أو مستودع عام أو شراء أو حذف أو تغيير صلاحيات خارجي
  واسع أو إنشاء مشروع عميل حقيقي دون اعتماد مستقل للأثر.
- إذا لم يُربط GitHub أو لم تُجهّز بيئة اختبار منشورة، يجوز تجهيز
  المسارات الداخلية واختبارها بعزل، لكن يبقى شرط الإغلاق غير متحقق.
