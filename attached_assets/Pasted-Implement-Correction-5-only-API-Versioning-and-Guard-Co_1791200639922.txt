==================================================
2. AUTHENTICATION GUARD CONVENTION
==================================================

Inspect the existing PlatformAuthGuard and @Public behavior.

Establish and document one explicit convention.

The preferred convention is:

- Protected application routes explicitly use PlatformAuthGuard.
- Public routes explicitly use @Public().
- Infrastructure routes such as health/readiness/docs remain outside normal authentication.
- Authentication must never be inferred from tenant hostname, request body, query parameters, or arbitrary headers.

Do not silently make PlatformAuthGuard global unless the existing architecture clearly requires it.

If the existing code already has an explicit guard convention, preserve it and formalize it rather than redesigning it.

Ensure @Public remains a deliberate route-level exception.

==================================================
3. PLATFORM AUTHORIZATION GUARD
==================================================

Keep PlatformAuthorizationGuard separate from PlatformAuthGuard.

Authentication answers:

"Who is the authenticated platform user?"

Authorization answers:

"Is this authenticated platform user allowed to perform this action?"

Do not combine them into one guard.

Authorization must continue to resolve permissions server-side.

Never trust:

- request body roles
- query permissions
- headers
- cookies
- client-provided role IDs
- client-provided permission IDs
- JWT permissions supplied by the client

Preserve the existing server-side permission resolution.

==================================================
4. GUARD ORDER / COMPOSITION
==================================================

Define and document the required ordering:

Authentication must happen before platform authorization.

A permission-protected route must not be able to execute authorization against an unauthenticated request.

Do not create a second authorization mechanism.

Do not duplicate permission checks inside controllers unless an existing business rule genuinely requires it.

Keep guards focused:

PlatformAuthGuard:
- token
- user
- tokenVersion
- session
- account status
- authentication context

PlatformAuthorizationGuard:
- required platform permissions
- platform role/permission resolution
- authorization decision
