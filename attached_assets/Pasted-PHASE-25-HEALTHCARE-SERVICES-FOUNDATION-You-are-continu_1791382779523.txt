VALIDATION

Implement strict DTO/schema validation.

Reject:
- missing required name
- invalid IDs
- empty strings where not allowed
- oversized fields
- HTML-like description content
- attempts to modify protected ownership/security fields
- cross-tenant service references
- invalid lifecycle transitions

PATCH behavior must distinguish:
- omitted field = unchanged
- explicit null = only allowed where the field is nullable and should be cleared
- empty update = rejected

Follow the validation behavior already established by previous phases.

TENANT ISOLATION

- returned to Tenant B
- updated by Tenant B
- transitioned by Tenant B
- readable using another tenant's service ID

Use tenant-qualified queries/repositories consistently.

Do not rely on:

Use the established tenant-scoped repository pattern.
