# Thanarah MongoDB Adapter Matrix

**Updated:** 2026-11-04
**Test topology:** Disposable three-member MongoDB 7.0.17 replica set on loopback; synthetic database and fixtures only.

| Port(s) | Candidate implementation | Transaction / atomicity approach | Verified locally | Remaining gate |
|---|---|---|---|---|
| PlatformAuthorizationPersistencePort | `MongoPlatformAuthorizationRepository` | Snapshot transaction and one shared session for cross-collection reads | Yes: role, permission, missing/malformed references, concurrent revocation snapshot, sanitized failure, primary stepdown | No cross-adapter MySQL differential; code/value parity and lifecycle behavior remain unapproved |
| TenantPersistencePort | `MongoTenantRepository` | Atomic status compare-and-set; pre-provisioned unique slug and listing indexes | Yes: create, reads, filtered stable pagination, duplicate index, lifecycle status transitions in disposable replica set | Slug collation and MySQL differential behavior are not proven; candidate remains unregistered |
| TenantMembershipPersistencePort | `MongoTenantMembershipRepository` | Snapshot transactions for reference validation and status change; shared per-tenant membership lock for owner bootstrap/status coordination | Yes: create/read/list/directory, active lookup, duplicate protection, lifecycle CAS, and owner protection in disposable replica set | Membership-role assignment adapter is still missing; cross-port owner races, MySQL transaction semantics, and service-error parity are not proven |
| TenantStaffPersistencePort | `MongoTenantStaffRepository` | Snapshot transaction for active tenant/member/user validation and insertion; shared tenant membership lock coordinates with membership status changes | Yes: eligible membership creation, duplicate prevention, scoped reads, updates, and lifecycle CAS in disposable replica set | Candidate is unregistered; MySQL locking/reference-race, membership/user lifecycle parity, and service-error mapping remain unverified |
| FeaturePersistencePort | `MongoPlatformFeatureRepository` | Atomic expected-status updates | Yes: reads, ordering, case-insensitive lookup, uniqueness, update and status compare-and-set | `en` strength-1 collation is not proven equivalent to MySQL `utf8mb4_unicode_ci`; service error mapping also needs review |
| PlanPersistencePort | `MongoPlatformPlanRepository` | Snapshot transactions for relation reads/writes; unique pair index for attachment | Yes: plan lifecycle, relation reads, attach/configure/detach, duplicate handling | Plan-key collation parity, JSON/SQL-null semantics, and service error mapping are not proven |
| TenantEntitlementPersistencePort | `MongoTenantEntitlementRepository` | Snapshot transaction across plan, feature, and association reads | Yes: plan/feature missing, missing/disabled association, entitled and inactive-feature outcomes | No MySQL differential across case/accent behavior or concurrent lifecycle changes |
| TenantQuotaPersistencePort | `MongoTenantEntitlementRepository` | Snapshot transaction across association, plan, and feature | Yes: enabled active configuration and unavailable states | No MySQL differential; quota JSON-vs-SQL-null representation still needs explicit parity evidence |
| PlatformUserPersistencePort | `MongoPlatformUserRepository` | Single-document atomic update pipeline for failed-login increment and lockout | Yes: concurrent increments, lockout, reset, and case-insensitive lookup | No MySQL differential for lock timing/threshold races; email collation differs potentially; service error mapping is not approved |
| PlatformSessionPersistencePort | `MongoPlatformSessionRepository` | Mongo transaction for user-reference validation, token-history insertion, session rotation, and reuse compromise | Yes: user-referenced create, rotation, simultaneous same-token rotation/replay, lifecycle lookup and transitions on the disposable replica set | Transaction retry/uncertain commit, session-specific failover, and MySQL behavior are not proven |
| FacilityPersistencePort | `MongoFacilityRepository` | Tenant reference check on create; atomic tenant-scoped updates and status compare-and-set | Yes: missing-parent rejection, cross-tenant isolation, stable pagination, rename, and lifecycle CAS on the disposable replica set | Candidate is not registered; transaction/reference race, facility-specific failover, MySQL error/collation parity, and broader service-contract behavior remain unverified |
| PlatformAuditPersistencePort | `MongoPlatformAuditRepository` | Transactionally validate user/tenant references with audit insert; security resolution is OPEN-only compare-and-set | Yes: valid and missing references, audit duplicate/idempotency lookup, security-event creation, and one-time resolution on disposable replica set | Candidate is not registered; source error/FK delete semantics, service-level event-delivery guarantees, MySQL parity, and failover/uncertain-commit evidence remain unverified |
| HealthcareCatalogPersistencePort | `MongoHealthcareCatalogRepository` | Tenant-active check before mutation; collation-backed unique tenant/name indexes; conditional lifecycle update | Yes: department/specialty create, case-insensitive duplicate name, inactive tenant, tenant-scoped reads, update, and lifecycle CAS on disposable replica set | Candidate is not registered; Mongo collation equivalence to MySQL, tenant-state races, and service/error parity remain unverified |
| ServiceCatalogPersistencePort | `MongoServiceCatalogRepository` | Tenant-active check before mutation; unique tenant/name and partial non-null tenant/code indexes; atomic lifecycle CAS | Yes: null-code duplicates, case-insensitive name/code conflicts, conflict kinds, counts, scoped reads, updates, and lifecycle CAS | Candidate is not registered; MySQL collation and nullable-unique semantics, tenant-state races, and service/error parity remain unverified |
| SubscriptionPersistencePort | `MongoSubscriptionRepository` | Snapshot transactions plus a per-tenant lock document for overlap checks and lifecycle transitions | Yes: active period overlap rejection, concurrent overlapping creation serialization, current-subscription query, and lifecycle transitions on the disposable replica set | Candidate is not registered; plan/tenant status race parity, SQL isolation equivalence, uncertain commit, and MySQL parity remain unverified |
| TenantRolePersistencePort | `MongoTenantRoleRepository` | Snapshot transactions for permission replacement and initial owner bootstrap; stable assignment IDs and tenant bootstrap lock | Yes: role metadata, permission replacement, system-role protection, default role bootstrap, owner assignment, and catalog/bootstrap failure handling | Candidate is not registered; MySQL collation, cross-port coordination, tenant-lock parity, and error mapping remain unverified |
| BranchPersistencePort | `MongoBranchRepository` | Snapshot transactions for parent validation and branch writes; tenant/facility-scoped mutations | Yes: active-parent checks, cross-tenant isolation, pagination, rename, and branch lifecycle updates | Candidate is not registered; parent status race with Facility/Tenant mutations, MySQL error semantics, and cross-port transaction parity remain unverified |

All seventeen candidates remain unregistered. Other generic document repositories do not implement their corresponding persistence ports. The Mongo indexes use case/accent-insensitive collation for some keys and emails, but that choice is not evidence of equivalence to the source MySQL collation.
